# Реестр рисков

**Срок:** пара 2 · **Обновляется:** на каждой вехе

| № | Риск | Вероятность | Последствия | План действий |
|---|---|---|---|---|
| 1 |Готовая модель (LLM) уже неплохо справляется с генерацией упражнений | низкая | 	нужно переформулировать тему/сузить её | заранее прогнать 20 текстов через готовую модель по всем трём языкам, честно оценить и при необходимости сузить тему |
| 2 | Для корейского и китайского не хватает качественных исходных текстов разных уровней | средняя | задержка вехи 1 по этим языкам | заранее подобрать 2–3 источника текстов на язык, английскую версию довести до рабочей первой, чтобы не терять темп |
| 3 | Не хватает собственных знаний корейского/китайского для проверки качества сгенерированных упражнений | средняя | ошибки в упражнениях останутся незамеченными до защиты | найти эксперта (например, преподавателя) и договориться о разовой проверке выборки |
| 4 | Модель не превосходит базовое решение | высокая | сложно обосновать ценность решения на защите | заложить baseline с самого начала, сравнивать с ним на каждой вехе, а не только в конце |
| 5 | Один из участников по какой-либо причине не может выполнить свою часть работы | низкая | полностью останавливается часть работы | общаться в процессе выполнения проекта как можно больше, вести документацию и промпты так, чтобы любой участник мог подхватить чужую часть |

**Риски, характерные для этих проектов:**

- собранных данных меньше расчётного;
- доля дубликатов и мусора выше ожидаемой;
- источник закрыл доступ;
- разметка из источника оказалась ненадёжной;
- модель не превосходит базовое решение;
- вычислительных ресурсов недостаточно;
- контракт API пришлось менять после написания интерфейса;
- участник команды выбыл;
- модель слишком тяжёлая для публикации.
